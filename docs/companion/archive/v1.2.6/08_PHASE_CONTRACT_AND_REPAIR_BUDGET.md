# Progress Guard — Repair Budget Removed

Runtime 1.2.4 has no numerical repair budget. Counts may be recorded for diagnostics but never authorize or block work.

The progress guard compares material findings, deterministic test outcomes, candidate-file identities and route. Work continues automatically while the fingerprint changes in a productive direction. Two consecutive identical/no-progress outcomes produce one hard stop.

The owner is never asked for an “extra batch.” Owner decisions are limited to requirement/scope change, destructive action, release/publication, credentials/private data/paid network access, material risk, normative protocol change, or an unavailable required capability.
